# Clause Hunter｜合同找茬大师

在线使用：[https://lpddog.github.io/clausehunter/](https://lpddog.github.io/clausehunter/)

源码仓库：[LPDDOG/clausehunter](https://github.com/LPDDOG/clausehunter)。推送 `main` 后自动测试并部署。

纯前端中文合同审查训练网站。原生 HTML、CSS、JavaScript，无后端、数据库、付费API、字体或图标外部依赖。需要 Node.js 20 以上运行开发和构建脚本，无需 `npm install`。

## 本地运行

在项目文件夹打开终端：

```sh
npm run dev
```

浏览器打开终端显示的 `http://127.0.0.1:4173`。停止服务按 Ctrl+C。不要直接双击 index.html：浏览器的 ES 模块需要 HTTP 服务。

```sh
npm test
npm run build
npm run preview
```

构建结果在 `dist/`。预览也使用4173端口，运行前先停止开发服务器。可设置环境变量 `PORT` 更换端口。

## 已实现

- 首页、主题筛选、五类合同十个独立关卡，每关六条条款、三个风险点。
- 条款标记及取消、自动保存、提交二次确认、详细报告、风险/误判/漏判状态、重新挑战。
- 三十份独立风险解析，含原因、商业影响、参考修改文本、可复制条款及公开法律来源。
- 独立合同修订编辑器，保存草稿、对照参考方案、字面关键词自查。规则不代表文本质量判断，不使用AI批改。
- 本地成绩、最高分、平均分、主题最佳均分图、五枚成就；重置二次确认。
- 每次挑战的历史复盘、关卡筛选与每页10条的分页；重新挑战后仍可回看过去的标记。
- JSON备份导出与合并导入，支持在本地站点和线上站点之间手动迁移；重复记录去重并优先保留本机草稿。
- 修订参考对照及关键词提示随输入实时更新，不会重建编辑框或打断光标。
- 自动整理最近一次完整挑战中的错漏，提供单条盲答回练、主题筛选、复习进度保存及备份迁移；不改动挑战成绩。
- 深浅主题、移动布局、键盘操作、语义按钮、可见焦点、原生确认对话框、减少动画偏好支持。

## 评分和统计

`max(0, round(100 × 正确识别数 / 实际风险数 − 15 × 误判数))`。

漏判减少识别比例，不再另扣；全对且无误判100分，全部漏判0分，不能低于0分。最佳分取该关全部挑战最高值，平均分取所有已提交挑战分数平均值。主题图取该主题**已完成关卡最佳分的平均值**，不是所有挑战平均值。零误判成就要求识别至少一处风险，避免空白提交解锁。

修改案例：在 `cases.js` 调整背景、立场、目标及条款文本；条款的 `risk` 对应 `risks.js` 中的键，没有风险填 `null`。`make()` 按案例ID及序号生成唯一条款ID。新增风险解析时填写所有字段与关键词。正常条款可用第四个参数添加专门的中性说明。**不要随意改变已有案例或条款ID**，否则旧记录无法正确对应；大改题库时建议先重置记录。首页的数量及成就说明目前按十关配置，扩展数量时同步修改展示文案和测试约束。

`src/config.js` 中填写 `githubUrl`，关于页即出现可访问的仓库链接。当前游戏风格配色在 `src/game.css` 开头变量中修改，通用布局保留在 `src/styles.css`。全部使用系统字体及内置SVG/文字图标，无需下载商业素材。

训练记录保存在当前站点、当前浏览器的 `clause-hunter-v1` LocalStorage。浏览器禁止存储或空间不足时会提示，当前会话仍可运行。隐私模式或清理站点数据可能删除记录。修订文本仅按纯文本渲染，避免将输入作为HTML执行。

## 复盘与备份使用方法（v1.1）

打开「我的成绩」，在页面下方的挑战历史中点击「复盘本次」，即可查看那次提交的正确识别、漏判、误判与逐条报告。旧版本记录也能打开，不会清除已有成绩；历史报告按照当前题库解析，不保存旧版题库快照。

迁移步骤：在原设备或原站点的「我的成绩」点击「导出记录」，保存JSON文件；再在新设备或新站点点击「导入备份」，选择该文件，核对新增数量后确认合并。文件仅在浏览器本地读取，不上传服务器。备份包含训练成绩、条款标记与修订草稿，请妥善保管。

同一关卡、同一提交时间及同一组标记视为重复挑战，只计一次。不同时间提交的相同答案仍是独立记录。本机已有审查进度和非空修订草稿优先保留；主题偏好不随备份改变。导入分数及成就按当前题库重新计算。支持不超过5MB、最多10000次挑战的本站v1备份，每份修订草稿不超过20000字；无效文件会整份拒绝，不会部分写入。浏览器无法保存合并结果时，也不会替换当前内存记录。

## 错漏回练（v1.2）

导航栏或「我的成绩」中点击「错漏回练」。系统根据各关最近一次完整挑战，整理漏判及误判条款。回练前隐藏历史错误类型和答案，先阅读背景及审查方目标，再选择「标记为潜在风险」或「本场景下无明显风险」；提交后展示结果与解析。支持键盘操作及合同主题筛选。

单条回练只更新复习进度，不改变挑战次数、历史分数、最佳成绩或成就。答对后进入「本轮已答对」，答错仍待复习；再练一次会隐藏答案重新作答。「本轮已答对」仅表示本次二选一判断符合教学答案，不代表完整法律能力评价。

重新提交整份合同时，会用该次挑战重建该关清单；最新挑战已全部判断正确则移出清单。新的错漏不会沿用上一轮的回练完成状态。判定最新挑战优先使用提交时间，导入旧记录不会因追加顺序覆盖较新的挑战。

回练进度纳入JSON备份，继续兼容v1.0／v1.1记录与备份。合并时先匹配最新挑战，再选较新的回练结果；旧备份没有回练字段时，保留本机已有进度。复习数据损坏时只重置该字段，保留完整挑战记录与修订草稿。

## 纸面侦查游戏界面（v1.3）

视觉采用奶油色纸张、墨绿色线框、可按压按钮、主题关卡地图与徽章；支持相同风格的深色模式。首页热身题可直接点选，仅用于演示，不写入成绩。地图按五个主题分区展示十个关卡，全部自由开放；探索进度、完成状态、星标均从已有本地记录计算。

星标显示本关最佳成绩：90～100分为3星、60～89分为2星、1～59分为1星，0分或未挑战为0星；结果工作台按本次成绩显示星标。星标只作视觉反馈，不修改评分算法、历史记录、成就或复习状态。没有职业等级、角色剧情或倒计时。

## GitHub Pages 部署

1. 在 GitHub 新建仓库，把本项目所有源码文件（包括 `.github` 目录）上传到仓库的 `main` 分支。
2. 进入仓库 **Settings → Pages → Build and deployment**，将 Source 选为 **GitHub Actions**。
3. 推送代码后，进入 **Actions** 查看 `Deploy GitHub Pages`。也可以在这个工作流页面点击 **Run workflow**。
4. 成功后到 Pages 设置页打开网址，通常是 `https://用户名.github.io/仓库名/`。

工作流使用 Node 22，先测试，再构建并上传 `dist/`，最后部署。无需配置密钥、数据库或环境变量。如果默认分支不是 `main`，修改工作流的 `branches`。

所有资源均使用相对路径；页面导航使用 `#/...`，刷新关卡不会触发服务器寻找不存在的子页面。支持仓库子路径及用户主页站点，无需修改 `base`。手动静态部署时将 `dist/` **内部文件**放到托管目录根部，保持 `src/` 和 `assets/` 的结构；也可用 GitHub Pages 的分支部署，把构建产物放进发布分支根目录。

## 内容边界与来源

案例虚构，风险等级为教学中的相对评级。偏向对方不意味着违法，商业风险和谈判优化单独标注。初版内容由AI辅助编写，尚未经过执业律师逐案复核。

涉及条号的劳动合同、民事免责及个人信息委托处理规则已对照官方公开文本；不确定的事项提供一般性分析，不补造条号。来源链接在风险报告及关于页中可查，核对日期2026-10-23。跨境案例提示CISG、补充准据法和交易背景的关系，贸易术语需结合ICC正式规则及运输方式另行审查。真实交易还需核对最新修法、司法解释、当地口径及行业规定。

本网站内容仅用于法律学习和合同审查训练，不构成正式法律意见。具体合同风险应结合交易事实、适用法律及专业意见判断。
